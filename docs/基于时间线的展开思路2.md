# 基于 Timeline 直接展开到动作层的策略

看了你这份简·爱的 Phase 1 数据，质量很高——24个子时期，每个都有 core_situation、opening_event、closing_event，粒度已经到了"场景级别"。这是一个非常好的展开基点。

## 核心思路：子时期本身就是一个"场景容器"

你已经有了场景的边界（opening/closing）和情境描述（core_situation），接下来要做的是**在每个子时期内部枚举这段时间里发生的具体动作序列**。思路是：

```
sub_period → 动作序列（外部动作 + 内部动作，按时间/因果排列）
```

不需要交叉枚举，因为子时期本身已经限定了时间、空间、在场人物、角色身份。你只需要**在这个框内做纵深展开**。

---

## 展开策略：三轮递进

### 第一轮：叙事展开——这段时间里发生了什么

```yaml
prompt: |
  人物：{character}
  人生阶段：{life_stage.name}
  子时期：{sub_period.name}
  时间范围：{sub_period.time_range}
  核心处境：{sub_period.core_situation}
  开端事件：{sub_period.opening_event}
  结束事件：{sub_period.closing_event}

  请详细列举在这个子时期中，{character} 做了哪些具体的事情？

  要求：
  1. 按时间/因果顺序列举，从开端事件展开，到结束事件收束
  2. 粒度要求：一个"动作"是此人在一个场景中的一次具体行为
     ✓ "简将烛台放在桌上，站在门外倾听三楼的动静"
     ✗ "简在桑菲尔德生活了几个月"（太粗）
  3. 既包括对外的行动（说了什么、做了什么），也包括对内的行动
     （做了一个决定、压抑了一种冲动、改变了对某人的看法）
  4. 不要只列重大事件，日常的、重复性的、过渡性的动作也要列
  5. 如果这个子时期跨越较长时间，区分"具体的一次性事件"和"持续/重复的行为模式"
```

这一轮的产出是**动作列表的初稿**。对于简·爱这种文学人物，LLM对原著的记忆相当细致，单个子时期应该能产出10-30个动作。

### 第二轮：维度补充——追问被遗漏的侧面

第一轮通常会偏向"推动情节的动作"，遗漏那些不推动情节但塑造人物的部分。用一个针对性的追问：

```yaml
prompt: |
  人物：{character}
  子时期：{sub_period.name}
  核心处境：{sub_period.core_situation}

  已提取的动作列表：
  {round_1_results}

  以上列表可能遗漏了以下类别的动作，请逐一检查并补充：

  【内心活动类】
  - 此人在此时期形成或改变了哪些判断/信念？
  - 有哪些情绪上的波动、压抑或爆发？
  - 做过哪些自我说服、自我劝阻、内心辩论？
  - 对未来有过什么期待、恐惧或规划？

  【关系互动类】
  - 与在场人物有哪些非关键但存在的互动？（日常对话、观察、回避）
  - 对不在场的人物有过什么思念、怨恨或牵挂？

  【身体与环境类】
  - 身体状态如何？（疲劳、饥饿、病痛、感官体验）
  - 与物理环境的互动？（空间移动、物品使用、对环境的感知）

  【习惯与重复行为】
  - 此时期有无重复性的日常行为？（每天做什么、固定习惯）

  只补充新的，不要重复已有的。
```

### 第三轮：反事实与未选择路径——挖掘"没做的事"

这一轮特别有价值，因为你的 belief-observation-action 格式需要展现**决策空间**——角色面前有多条路，选择了其中一条：

```yaml
prompt: |
  人物：{character}
  子时期：{sub_period.name}
  已提取的动作列表：
  {round_1_results + round_2_results}

  对于以上动作中涉及选择/决策的时刻，请指出：

  1. 此人当时还有哪些备选方案但没有选择？
  2. 此人克制了哪些冲动？（想做但忍住了）
  3. 此人回避了什么？（本可以面对但选择逃避）
  4. 有没有"差点做了但被打断"的行动？

  对每个"未选择路径"，简述：
  - 是什么阻止了此人选择那条路（道德约束？能力不足？外部阻拦？信息不足？）
```

这一轮的产出不是独立的动作，而是**对已有动作的决策上下文增强**——直接丰富了后续转换为 belief-observation-action 时 belief 中的 alternatives 和 reasoning 部分。

## 示例：实际对简·爱某个子时期的展开效果预估

以 `"红房子事件与觉醒反抗"` 为例：

**第一轮预期产出：**
```
外部动作：
1. 躲在窗帘后面安静读书
2. 被约翰·里德发现并叫出来
3. 被约翰用书砸中头部，太阳穴流血
4. 猛扑向约翰进行反击（抓、踢、咬）
5. 被仆人和里德太太合力制服
6. 被拖入红房子并锁上门
7. 在红房子中检视镜中自己的倒影
8. 在黑暗中看到墙上游移的光斑，误以为是鬼魂
9. 惊恐尖叫并拼命捶门求放出去
10. 昏厥倒地

内部动作：
11. 在被约翰打时，内心第一次形成清晰判断："这不公平"
12. 在反击的瞬间，恐惧被愤怒压过
13. 在红房子中回忆舅舅的形象，想象他的鬼魂可能出现
14. 恐惧与委屈交织，产生"不如死了"的念头
15. 对贝茜和阿伯特不肯开门感到被全世界抛弃
```

**第二轮补充：**
```
16. (身体)被书砸中后感到太阳穴剧痛，血流到脖子上
17. (关系)听到贝茜在门外低声说"可怜的孩子"但不敢开门
18. (环境)在红房子里感知到房间极冷、光线随日落消失
19. (信念)第一次模糊地想到"也许我可以离开这里"
20. (习惯)在被发现之前，她已经养成了在窗帘后躲藏读书的固定模式
```

**第三轮（未选择路径）：**
```
21. 面对约翰的殴打，备选是像往常一样默默忍受——这次没选择忍受
    阻止因素：痛苦的累积超过了忍耐阈值
22. 在红房子里可以选择安静等待以求尽快被释放——但恐惧使她无法理性行动
23. 反击约翰时可以选择告状而非动手——但她知道告状从来没有用
```

一个子时期产出约20-30条，24个子时期总计约500-700条动作。这是**单人物**的产出量。

## 对不同密度的子时期的处理

你的 timeline 中有两种子时期：

```
密集型：单一场景，时间很短（如"红房子事件"——一个下午）
  → 第一轮就能挖出高密度细节

稀疏型：长时间跨度（如"改革后的平静求学"——约五年）
  → 需要额外一步：先让LLM把长周期分解为若干"典型场景"
```

对稀疏型，加一个中间步骤：

```yaml
prompt: |
  子时期：{sub_period.name}
  时间跨度：{sub_period.time_range}（注意：这是一个较长的时间段）
  核心处境：{sub_period.core_situation}

  这段时间内没有单一的戏剧性事件，而是一段相对平静的持续状态。
  请列举此时期中可能发生过的5-8个"典型场景"，
  即能代表此人在这段时间里生活状态的具体时刻。

  示例格式：
  - 场景名：某个冬夜在坦普尔小姐房间的学习
    简述：坦普尔小姐邀请简到自己房间烤火，两人讨论...
```

然后对每个典型场景再用三轮展开法提取动作。

## 管线流程总结

```
对每个 character:
  对每个 sub_period in timeline:
    if sub_period.time_span > threshold:
      典型场景分解 → scenes[]
    else:
      scenes = [sub_period本身作为单一场景]
  
    对每个 scene:
      Round 1: 叙事展开 → actions_draft
      Round 2: 维度补充 → actions_enriched
      Round 3: 未选择路径 → decision_context
    
      合并 → scene_actions
  
    合并所有scenes → sub_period_actions

  合并所有sub_periods → character_raw_actions

  去重/合并 → character_final_actions

  转换为 belief-observation-action 格式 → training_samples
```

### 调用量估算（以简·爱为例）

```
24个子时期
  其中约6个是稀疏型，需要场景分解（+6次调用，每个产出5-8场景≈40场景）
  密集型18个子时期 + 40个展开场景 = 58个场景单元
  每个场景单元3轮 = 174次LLM调用

单人物: ~180次调用
5000人物: ~900,000次调用（Phase 2总计）
```

相比多轴交叉的500,000次，调用量略多但每次调用的**上下文更聚焦、产出更直接可用**，且去重难度大幅降低——因为每次调用的范围是一个狭窄的场景窗口，重复的概率天然就低。

---

## 关于去重

这个方案下去重会简单很多。主要的重复来源是：
- 相邻子时期的 closing_event 和 opening_event 描述的是同一个事件
- 第一轮和第二轮之间的局部重叠

处理方式：
1. 相邻事件重复：在prompt中明确指出"opening_event已经作为上一个子时期的closing_event被提取过，本轮从此事件之后开始"
2. 轮次间重复：第二轮prompt已经包含了第一轮结果作为排除列表，LLM通常会自觉避免

真正需要做的去重主要是**语义级别的**——同一个动作被不同措辞描述了两次。这个可以用embedding相似度做一轮后处理筛选，不需要在生成阶段解决。
