当前项目的目标是分析LLM所熟悉的角色来合成SFT语料，管线中有需要LLM进行信息加工的节点。
经常会需要LLM产出多个结构化的结果，之前的实验已发现通过工具调用的方式来让模型产出结构化结果，要比正文中的结构化文本更稳定也更灵活。将期望的产出结构包装为tool schema，收集LLM的工具调用，就得到了结构化产出。还可以在工具调用后进行验证，将验证结果作为工具调用结果反馈给LLM，实现一定的结构自愈能力。

设想中的LLM节点如下：
  - 能通过`系统提示词`和`api_client`这两个最小参数创建新实例。
  - 能执行工具调用循环，至少能同步执行。
  - 能收集工具调用得到结构化产出。
  - 未来能拓展更多非结构化产出工具，比如上网查资料和操作文件系统。
  - 能通过收集工具调用，来获知任务的执行情况：成功，遇到解决不了的困难而失败，可继续但未完成（因向用户报告进度或提问而停止）

典型用法如下：
  1. 创建实例，“你是一个历史人物分析专家...”
  2. 提供结构化产出工具，`("output_life_stage", {<json schema>}, "用此工具输出人物的一个人生阶段。")`
  3. 用user prompt提供任务，“请分析人物{X}经历了哪些主要的人生阶段，用工具调用来输出结构化结果，每个阶段一次工具调用。”
  4. 执行tool loop直到工具调用循环结束，并收集所有结构化产出的工具调用，验证结构，通过工具调用结果给LLM反馈。
  5. 通过user prompt询问LLM任务执行情况，“我是一个调度器程序，看不懂自然语言，请通过工具调用来告诉我刚刚的任务执行状态：成功，遇到了解决不了的困难，因汇报进度或提出问题而停止。”
  6. 输出任务执行结果：LLM的最终response文本，收集到的所有合法结构化产出，最终任务执行状态，tool loop过程中的LLM正文输出（有时候final response文本不完整，会有部分内容位于最后一次工具调用之前）
